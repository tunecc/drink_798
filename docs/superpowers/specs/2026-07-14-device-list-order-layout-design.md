# 设备列表排序与密集布局设计

日期：2026-07-14  
状态：已确认  
方案：本地偏好 + 最小依赖（方案 A）

## 1. 目标与范围

### 1.1 目标

- 用户可把常用设备拖到列表前面，顺序本地持久化，重启后仍保持。
- 主页设备展示更密，并支持「紧凑单列 / 双列网格」一键切换，偏好本地记住。

### 1.2 范围内

- 主页「我的设备」标题栏：布局切换 + 排序入口。
- 紧凑单列 / 双列网格两种展示。
- 拖拽排序模式（Flutter 内置 `ReorderableListView`）。
- `SharedPreferences` 存顺序与布局偏好（与现有设备备注同层）。

### 1.3 范围外

- 服务端同步顺序。
- 新增第三方拖拽库。
- 修改接水 / 扫码 / 删除等业务逻辑。

### 1.4 成功标准

- 拖完后刷新或杀进程重进，顺序仍在。
- 布局切换即时生效，重启后恢复上次选择。
- 排序过程中不误触接水；接水中不允许改序。
- 新设备出现时落在自定义顺序末尾；已删除 id 从 order 中忽略。

## 2. 背景与现状

- 应用：Flutter + GetX 饮水 APP（`drink_water_app`）。
- 主页设备区为纵向大卡片 `ListView`（`home_page.dart` 中 `_buildDeviceGrid`），卡片 padding / 间距偏大，设备多时需频繁滑动。
- 设备顺序直接来自 API `getDeviceList()`，本地无排序偏好。
- 设备备注已通过 `SharedPreferences` 的 `device_note_{id}` 持久化（`home_controller.dart`）。
- 现有「设备管理」底部弹窗负责删除与添加，不承担排序。

## 3. 交互与 UI

### 3.1 标题栏（「我的设备」右侧）

从左到右：

| 控件 | 作用 |
|------|------|
| 布局切换图标 | 在紧凑单列 / 双列网格间切换；当前模式高亮或更换图标（如 list ↔ grid） |
| 排序图标 | 进入 / 退出排序模式 |
| 添加 | 保留现有扫码添加；优先继续用 `TextButton.icon`，小屏过挤时再收成 `+` 图标 |

### 3.2 布局模式

**紧凑单列（默认）**

- 仍为单列列表，但更矮：内边距约 10–12、项间距约 6–8、图标约 20、名称字号约 14–15。
- 仍显示：图标 + 名称（备注优先）+ 选中勾；编辑备注保留小按钮或长按（与现有一致）。

**双列网格**

- `GridView`，`crossAxisCount: 2`，子项更小。
- 每格：图标 + 名称（最多 1–2 行省略）+ 选中态描边 / 勾。
- 点选设备、长按改备注行为不变。

布局偏好键：`device_list_layout` = `list` | `grid`。

### 3.3 排序模式

1. 点排序图标 → 进入排序模式。
2. 标题旁显示完成态（「完成」文案或排序图标变为勾）。
3. **排序时始终使用单列可拖列表**（即使当前是双列）：避免双列拖拽复杂度；完成后按当前布局偏好回显。
4. 每行显示拖动手柄；长按行或手柄拖动重排。
5. 排序模式下：禁止选设备接水、禁止打开备注编辑（避免与拖动手势冲突）。
6. 点「完成」或再点排序图标 → 退出排序并确保顺序已保存。
7. **接水中**：排序按钮禁用，或点击提示「正在接水中，请先结算」。

排序时可在列表上方显示一行轻提示：「拖动调整顺序」。

### 3.4 手势关系

| 模式 | 点按 | 长按 | 拖动 |
|------|------|------|------|
| 正常 | 选中设备 | 编辑备注 | 滚动列表 |
| 排序 | 无业务动作 | 开始拖 | 重排 |

## 4. 数据与持久化

### 4.1 SharedPreferences Keys

| Key | 类型 | 含义 |
|-----|------|------|
| `device_order` | `List<String>`（设备 id 有序） | 用户自定义顺序 |
| `device_list_layout` | `String`：`list` / `grid` | 布局偏好 |
| `device_note_{id}` | 已有 | 备注，本设计不改 |

### 4.2 加载与排序规则

1. API 拉取设备列表。
2. 加载本地备注（现有逻辑）。
3. 按 `device_order` 重排：
   - 在 order 中且仍存在的 id → 按 order 排列。
   - **新设备**（API 有、order 无）→ 接到末尾。
   - order 中已删除的 id → 忽略，下次保存时清理。
4. 写入内存 `deviceList` 并刷新 UI。

### 4.3 保存时机

- 拖拽 `onReorder` 后立即写入 `device_order`（防中途杀进程丢序）。
- 布局切换时立即写入 `device_list_layout`。

### 4.4 选中索引

- 重排后按 **设备 id** 找回选中项，不直接复用旧 index。
- 删除设备后逻辑保持现有；重排时同步修正 `selectedDeviceIndex`。

## 5. 实现落点

| 文件 | 改动 |
|------|------|
| `lib/features/home/home_controller.dart` | 加载后应用顺序；`reorderDevices`；`setLayoutMode`；读写 prefs |
| `lib/features/home/home_page.dart` | 标题栏图标；紧凑单列 / 双列；排序模式 `ReorderableListView` |
| 可选纯函数 | `applyDeviceOrder(devices, orderIds)`，便于单元测试 |

约束：

- 不新增第三方依赖。
- 不改 API。
- 默认不改 `DeviceModel` 字段结构。

## 6. 边界与错误处理

- prefs 未就绪：与备注相同，先 `_initPrefs` 再读写。
- 空列表：不展示有效排序操作，或点击无效果。
- 仅 1 台设备：可进排序模式，拖动无实质变化。
- 接水中：禁止进入排序；布局切换仍允许。
- 刷新 `loadDevices`：重新应用本地 order，不丢用户排序。

## 7. 验证方式

- 手动：拖序 → 杀进程重进 → 顺序保持。
- 手动：切双列 / 单列 → 重进 → 布局保持。
- 手动：新增设备落在末尾；删除设备后顺序仍合理。
- 手动：接水中点排序有提示。
- 可选：为 `applyDeviceOrder` 写 1–2 个单元测试。

## 8. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 双列下排序临时切到单列，用户可能困惑 | 排序模式内轻提示「拖动调整顺序」 |
| 标题栏控件变多，小屏拥挤 | 优先压缩间距；必要时「添加」收成图标 |
| 重排后选中态错位 | 始终按设备 id 映射 `selectedDeviceIndex` |

## 9. 方案选择记录

曾比较：

- **A. 本地偏好 + 最小依赖（采纳）**：`SharedPreferences` + `ReorderableListView`，无新依赖，与备注存法一致。
- **B. 专业拖拽包**：单列 / 双列原生拖拽更统一，但增加依赖与维护成本。
- **C. 服务端排序**：换机同步，但需后端接口，当前不在范围。
